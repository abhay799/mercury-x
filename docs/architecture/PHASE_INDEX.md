# MERCURY X Phase Index

This index describes the implemented control-plane responsibilities of Phase 0 through Phase 30. “Output” means a logical or control artifact unless a phase explicitly owns runtime behavior.

| Phase | Name | Responsibility | Key Inputs | Key Outputs | Safety Boundary |
|---:|---|---|---|---|---|
| 0 | Runtime Contract and Observability Foundation | Defines context, recovery state, provenance, tracing, runtime events, telemetry, and SLO evidence foundations. | Request/runtime context; evidence | Versioned foundational contracts and events | Context and provenance cannot be silently lost or rewritten. |
| 1 | Cognitive Gateway | Normalizes, validates, secures, admits, and hands off requests. | External request envelope; constraints; session identity | Canonical gateway request and admission/handoff artifacts | No bypass of normalization, security, idempotency, or canonical constraints. |
| 2 | Workload Intelligence Engine | Extracts signals and infers workload modality, complexity, capabilities, and constraints with calibrated evidence. | Canonical gateway request | Workload intelligence profile and calibration result | Describes workload needs; does not choose model, hardware, or placement. |
| 3 | AI Execution Graph | Builds and validates a logical computation DAG. | Phase 2 intelligence | Immutable logical execution graph and readiness result | Logical graph only; no physical resource assignment or execution. |
| 4 | Model Capability Fabric | Registers, discovers, and validates model capabilities and evidence. | Model capability declarations; graph requirements | Capability records and compatible candidates | No ranking, winner selection, graph assignment, hardware matching, or invocation. |
| 5 | Dynamic Model Composition | Instantiates bounded certified multi-model composition patterns. | Phase 3 requirements; Phase 4 candidates/evidence | Valid and rejected logical composition candidates | No ranking, scoring, winner selection, placement, or open-ended orchestration. |
| 6 | Adaptive Precision | Produces bounded precision profiles for exact model identities and revisions. | Composition stages; registered precision capability | Valid/rejected precision profiles | No preferred profile, hardware matching, placement, or runtime precision switching. |
| 7 | Elastic Model Morphing | Generates and validates registered depth, width, expert, adapter, and head/context variants. | Composition; precision profile; morph registry | Bounded morph profiles | No cross-family substitution, live self-modification, ranking, or runtime switching. |
| 8 | Agent Session Memory Fabric | Admits, stores, retrieves, compacts, expires, and isolates session-scoped memory. | Session artifacts and authorized queries | Session memory records and lifecycle results | No global, user-profile, or cross-session memory authority. |
| 9 | Global Context Memory | Promotes authorized session artifacts into governed tenant/workspace/project context. | Phase 8 records; namespace authorization | Versioned global-context records, retrievals, and consolidation results | Exact namespace authorization; no user-profile or cross-namespace access. |
| 10 | Context Prediction Engine | Predicts bounded future context needs from explicit evidence. | Current context and historical evidence | Context predictions with uncertainty/provenance | Prediction does not authorize retrieval or execution; unknown state remains explicit. |
| 11 | Semantic KV Cache | Validates and manages semantic KV-cache identities and reuse eligibility. | Context/cache identity and compatibility evidence | Cache records and reuse decisions | No unsafe or cross-boundary reuse; compatibility and provenance are required. |
| 12 | Disaggregated Cognitive Execution | Represents logical execution split across disaggregated cognitive stages. | Execution graph, context, capability evidence | Validated disaggregated execution plan | Does not silently choose unsupported physical resources or weaken constraints. |
| 13 | Hardware Personality Engine | Normalizes hardware profiles, probes, affinities, and capability evidence. | Hardware declarations and probe evidence | Versioned hardware personality profiles | No model selection, placement, scheduling, or unsupported capability inference. |
| 14 | Topology-Aware Compute | Models links, paths, locality, and topology constraints. | Hardware profiles and topology observations | Validated topology graph and path results | Topology evidence is descriptive; stale or impossible paths fail closed. |
| 15 | Predictive Compute Placement | Predicts eligible placement candidates with explicit confidence and calibration state. | Requirements, hardware, topology, evidence | Placement predictions and candidate evidence | Prediction is advisory; it does not schedule or execute and cannot invent capacity. |
| 16 | Speculative Execution Mesh | Plans bounded speculative branches and verifies one authoritative result. | Placement candidates and execution segment | Speculation plan, branch events, verified committed result | Bounded branches; exactly one authoritative commit; losers are cancelled/discarded. |
| 17 | Adaptive Reasoning Budget v2 | Allocates bounded reasoning, verification, speculation, escalation, and aggregation effort. | Intelligence requirements; placement/speculation evidence | Reasoning budget and decision | Cannot reduce quality/confidence floors or hide uncalibrated uncertainty. |
| 18 | Quality-Aware Scheduling v2 | Performs evidence-backed admission, fairness, gang, backfill, and scheduling decisions. | Placement, reasoning budget, queue/resource evidence | Versioned scheduling decision | No admission on unknown evidence and no quality degradation to clear pressure. |
| 19 | Intelligence Contract Compiler v2 | Compiles typed SLA requirements into versioned intelligence SLOs. | SLA, metric registry, policy hierarchy, temporal targets | Fingerprinted Intelligence SLO and generic requirement envelope | Hard requirements cannot be weakened; ambiguity and conflicts fail closed. |
| 20 | Autonomous Compute Negotiator v2 | Evaluates feasibility and issues protected, leased compute offers requiring explicit approval when changed. | Phases 15–19 evidence; resource generation | Offers, approvals, agreement, negotiation history | Negotiation does not provision or execute; protected constraints never auto-degrade. |
| 21 | Live AI Workload Migration | Coordinates eligibility, checkpoint, transfer, restore, verify, cutover, rollback, and ledger state. | Authorized agreement; source/destination state; checkpoint evidence | Migration plan, receipts, verification, cutover/rollback records | Exactly one authoritative executor after cutover; authorization cannot expand. |
| 22 | Self-Healing AI Infrastructure | Plans and verifies bounded recovery actions after detected failure. | Failure trigger, current generation, recovery candidates | Healing decision, ledger, and post-action verification | Unsafe recovery is rejected; healing is incomplete without verification. |
| 23 | Adversarial Scheduler | Challenges scheduler behavior with bounded adversarial scenarios. | Scheduling policy/state and attack scenario | Challenge result and invariant violations | Test/challenge function only; no direct production scheduling authority. |
| 24 | Counterfactual Compute | Evaluates hypothetical control scenarios without production side effects. | Baseline state and counterfactual scenario | Advisory counterfactual result | Simulation output cannot directly execute or authorize production actions. |
| 25 | Controlled Policy Evolution | Moves policy candidates through shadow, canary, approval, rejection, and rollback states. | Candidate policy and evaluation evidence | Promotion decision and rollback state | No autonomous production promotion; explicit approval is mandatory. |
| 26 | Federated Execution | Produces topology-aware placement decisions across explicitly identified execution domains. | Federation identity/capability and topology snapshot | Federated placement decision | No cross-domain authority expansion; domain identity and trust stay explicit. |
| 27 | Privacy-Aware Execution | Builds enforceable privacy envelopes from classification and policy. | Data classification, purpose, privacy policy, residency | Privacy envelope | Purpose, classification, privacy, and residency may not be weakened. |
| 28 | Datacenter Digital Twin | Simulates bounded datacenter scenarios with explicit calibration state. | Twin scenario and model/calibration evidence | Simulated twin result | Advisory simulation only; uncalibrated output is not measured production truth. |
| 29 | Control Intelligence | Produces bounded supervisory control signals and decisions. | Control objectives, evidence, system state | Control decision | Human-control gate remains authoritative; no hidden execution authority. |
| 30 | Production/Research Platform | Separates safe production and research modes and composes platform controls. | Platform configuration and certified phase artifacts | Platform status/mode result | Research mode cannot weaken production invariants or bypass human control. |
